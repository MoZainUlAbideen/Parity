How it works

Rules first. Measurements second. AI only where judgment is needed.

A language model asked "is this page accessible?" will confidently guess. Parity uses AI only for the questions rules and measurements can't answer, checks what the AI says, and tells you how sure it is.

The pipeline

What happens when you scan a page

1. Real browser

Headless Chromium loads the page on desktop (1366px) and mobile (390px), with screenshots of each. Bot-protection pages are detected and reported, never audited by mistake.

2. Rule engine

axe-core, the industry-standard open-source engine, checks the rendered page. Every finding is tied to its WCAG 2.2 success criterion and quoted from W3C's own text.

3. Agents

A contrast meter measures text over images from pixels. A keyboard agent presses Tab through the page. Alt-text rules catch file names and placeholders.

4. Vision model

Gemini looks at each image in context, judges its description and writes a better one. Code then cross-checks its answer before anything reaches the report.

Checking the AI

Why you can trust the AI parts

Consistency checks

If the model says a description is "inadequate" but its own suggested fix adds nothing new, the verdict is dropped. On real Gemini answers this removed every false alarm without losing a single real problem.

Recorded-answer tests

Real model answers are saved and replayed in the test suite, so a code change can't quietly bring old mistakes back, and tests run without calling the API.

Verified quotes

The assistant answers only from W3C's text. Every quote it gives is checked word for word against the passage; unverifiable answers are replaced with "I couldn't verify that".

Known limits

What Parity can't do (yet)

Not a conformance certificate

Automated checks, even with AI, can't prove a site meets WCAG. Use Parity to find and fix problems fast, then test with disabled people.

One page at a time

The demo scans a single public page. Pages behind a login, multi-page crawls and PDFs are on the roadmap.

Free-tier limits

The vision model checks up to 8 images per page on the live demo, and scans run one at a time. Bot-protected sites can't be scanned unless the owner allows Parity.

Under the hood

Tech stack

Browser automationPlaywright + Chromium, axe-core 4.13
VisionGemini (gemini-3.1-flash-lite) with retries, model fallbacks, disk cache and consistency checks
Knowledge baseAll 87 WCAG 2.2 success criteria and Understanding documents from W3C's GitHub, 1,092 passages
RetrievalBM25 + bge-small embeddings, fused with reciprocal rank fusion over rules
AnswersGroq (gpt-oss-120b), quotes verified word for word
BackendPython, FastAPI, job queue, rate limits, SSRF protection; Docker on Render
FrontendAccessible static site on Vercel (it passes its own audit)
Quality190+ tests, eval gates in CI, recorded-answer replay tests
